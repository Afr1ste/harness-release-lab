# Harness Release Lab

**给会执行操作的 Agent 做上线验收。**

[English](README.md) · [架构](docs/ARCHITECTURE.md) ·
[产品定位](docs/PRODUCT.md) · [验收证据](docs/ACCEPTANCE.md)

一次退款操作已经写入数据库，但返回结果丢了。Agent 再试一次，
到底产生了一条退款记录，还是两条？

这个项目直接检查业务数据库里的实际结果，把问题变成可以重复执行、
比较版本、阻止回归的测试。

![项目界面](docs/assets/dashboard.png)

## 立即运行

在项目目录中，使用 Python 3.11 或更高版本，建议先创建虚拟环境：

```sh
python -m pip install -e .
hrl demo
hrl serve
```

打开 <http://127.0.0.1:8787>。不需要模型密钥，不产生付费 API 请求。
目前还没有发布到 PyPI，需要从项目目录或交付的 wheel 安装。

默认演示包含两个确定性参考实现：有缺陷版本通过 4/8 项，
修正版本通过 8/8 项。它们用于证明测试能够发现问题，不代表模型能力分数。

## 真正接入 DeepSeek Harness

```sh
python -m pip install -e ".[dsh]"
hrl demo --dsh
```

这里启动的是官方发布的 DSH 运行时，通过官方 Python SDK 驱动，
加载原生 `lab_refund` 工具，调用本地模拟业务服务。
报告保留运行时版本、工具目录、模型协议请求、事件数量和真实业务状态。

模型输出由本地脚本控制，专门验证运行时和工具链。
“错误版本”是故意设计的重试策略，不是在声称 DSH 本身存在该缺陷。

## 能体现的工程能力

- Python 异步调用、数据校验、适配器接口和命令行工具。
- SQLite 事务、并发去重、写入后响应丢失、重启后的状态恢复。
- DSH 原生插件、Python SDK、Messages/SSE 协议、工具执行生命周期。
- 正反对照、故障注入、业务状态断言、回归拦截、JUnit。
- FastAPI 任务服务、单任务准入、可视化证据、离线报告。

技术价值来自这些真实工作链路，不能把测试场景的通过率包装成生产收益。

## 面向谁

优先面向 DSH 插件作者、运行时开发者，以及有退款、工单、资源创建等
业务写入的 Agent 团队。现阶段提供的是一个可运行的技术验证版本：
用户是否愿意持续使用、是否愿意付费，仍需要实际试用反馈。

项目支持加载额外的 DSH 配置补丁，检查插件修改是否破坏业务调用。
也支持用一个 Python 适配器接入自己的 Agent。
具体命令和故障插件复现见 [演示指南](docs/DEMO.md)。

## 当前边界

已实现的是本地单用户工具和一个退款账本模拟器；没有实现企业多租户、
生产流量代理、通用 MCP 代理、任意业务系统自动接入或真实模型评分。
脚本模型测试通过后，真实模型、提示词和业务系统仍需独立验证。

安装、测试、浏览器验证、已知限制和发布状态见 [验收记录](docs/ACCEPTANCE.md)。
