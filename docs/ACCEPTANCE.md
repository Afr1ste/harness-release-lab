## v0.2.3 修补与验证范围

- 包含下节的请求次数断言修复，保留原失败记录。
- 额外复现：给每次业务响应增加 300ms 延迟后，参考超时场景生成了正确的一笔
  业务记录，却因每次请求只有 200ms 而耗尽重试，错误地报告失败。
  新回归用例先失败，修改为 1 秒客户端截止时间、2 秒注入延迟后通过；
  普通请求仍使用 3 秒截止时间。HTTP 延迟用例采用相同的 1 秒 / 2 秒余量。
- 去掉依赖毫秒级调度精度的断言，检查故障注入与响应完成的事件顺序。
  独立的事件控制测试仍会在关闭入口过早返回时失败。
- 本地完整测试 68 项通过，见 [测试记录](evidence/v0.2.3-test-results.xml)。
- 五项相关检查每组连续执行五轮，任一失败立即终止；没有“重试直到绿灯”逻辑。
- CI 保存合成测试的 JSON 报告；网页任务测试失败时输出具体失败场景。
- 此阶段仅验证代码，未发布发行包。最终版本见上节。

## 建议验收顺序

1. 看失败报告：确认“说成功”和“实际执行正确”是两个不同检查。
2. 看修正报告：确认同一套业务约束能通过。
3. 看插件回归报告：确认工具不只服务于自写的参考程序。
4. 启动控制台，亲自运行一次。
5. 阅读 [产品定位](PRODUCT.md)，决定是否以这个切入口公开发布和找首批试用者。

这是有完整工作链路的工程验证版本；商业价值需要通过真实用户继续验证。
