- 真实付费模型、真实客户业务系统和生产流量。
- 第三方用户使用、付费需求、收入、GitHub 星数增长。
- 多租户部署、团队权限、计费或不可信代码隔离。
- PyPI 和 GitHub 公开发布：尚未执行。
- 离线 HTML 在本机外部浏览器中双击打开：内置浏览器禁止 `file://`，
  没有通过其他途径绕过这项策略。

29 项测试通过。后续升级测试客户端时应重新验证兼容性。

## 建议验收顺序

1. 看失败报告：确认“说成功”和“实际执行正确”是两个不同检查。
2. 看修正报告：确认同一套业务约束能通过。
3. 看插件回归报告：确认工具不只服务于自写的参考程序。
4. 启动控制台，亲自运行一次。
5. 阅读 [产品定位](PRODUCT.md)，决定是否以这个切入口公开发布和找首批试用者。

这是有完整工作链路的工程验证版本；商业价值需要通过真实用户继续验证。
